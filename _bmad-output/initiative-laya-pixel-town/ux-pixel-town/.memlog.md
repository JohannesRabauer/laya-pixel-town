- (decision) Concept: pixel town / ant colony sim, Java web app (LangChain4j + Laya batch endpoint). Many small pixel-art agents pick next activity each tick from a text state of needs/surroundings. Very visual, not a game, no player. Purpose: show how fast Laya decides. Chosen from brainstorm over traffic-controller idea.
- (decision) Flow: start screen with a few parameters (e.g. population) -> Start -> simulation view. ~100 tiny minimalist 2D animated people go about daily business in a town.
- (decision) Player is a god/observer, not a character: can pause the simulation, click a person to inspect needs, current action and the decisions being made (Laya). No direct interaction with people beyond inspecting.
- (decision) Working mode: fast path (draft both spines with [ASSUMPTION] tags). Purpose is showcasing Laya decision-making and speed.
- (assumption) Web, desktop-first; canvas rendering; Laya batch decisions per tick drive each agent's next activity.
